# Codex review of the plan (2026-11-21)

Run: `codex exec --sandbox read-only` over the spec, the palace code and the Tiramemsu source. Verbatim findings; resolutions are in design.md, "Review resolution".

1. **HIGH — [design.md:125, Supersede](specs/memory/tiramemsu/design.md:125): replay omits predicate constraints.** The algorithm retracts and inserts without checking the patched root’s uniqueness or applying cardinality replacement. Superseding Alice’s unique email to Bob’s email would therefore succeed. Tiramemsu explicitly runs these checks in `engine/supersede.rs:252`. **Fix:** add that pipeline before replay, plus tests for unique collisions and valid-time widening that overlaps another cardinality-one value.

2. **HIGH — [design.md:115, Assert/Create](specs/memory/tiramemsu/design.md:115): endpoint liveness is checked too early.** For a cardinality-one predicate, asserting `(s,p,StmtRef(old))` passes the initial check, then replacement retracts `old`, leaving the inserted statement referencing dead evidence. Derive has the equivalent risk when replacement retracts a support. **Fix:** recheck endpoints after replacement and supports when inserting support links. Tiramemsu does both; add rollback tests for these cases.

3. **HIGH — [design.md:78, invariant triggers](specs/memory/tiramemsu/design.md:78): copied replacement guards leave deletion holes.** Guards checking only `NEW.id`/`NEW.t` miss conflicts on `(tag,lex)` and `instant`. An in-memory probe successfully replaced term 1 with term 2 and deleted transaction 1 through its unique instant. `AUTOINCREMENT` does not prevent this; automatically allocated rowids are also undefined in BEFORE INSERT triggers. **Fix:** guard every unique conflict key and test replacement using omitted and different primary keys. [SQLite trigger documentation](https://sqlite.org/lang_createtrigger.html#cautions_on_the_use_of_before_triggers).

4. **HIGH — [design.md:78, invariant triggers](specs/memory/tiramemsu/design.md:78): historical views remain mutable through backdating.** Allowing any first retraction with `t_ret >= t_add` permits raw SQL to retract a statement at an already committed transaction, changing an earlier `AsOf` answer. Assertions can likewise use historical or nonexistent transaction numbers. Tiramemsu’s actual `ddl_date_guards.sql` prevents this. **Fix:** port the active-transaction/committed-watermark protocol and test backdated assertions and retractions.

5. **HIGH — [design.md:93, transaction locking](specs/memory/tiramemsu/design.md:93): the promised busy waiting is not configured for the pool.** Current `OpenDB` executes PRAGMAs once through `*sql.DB`; later connections need not inherit `busy_timeout` or foreign-key enforcement. File databases retain an unrestricted pool. A mutex per graph also does not cover other graph instances or drawer writes. **Fix:** initialize connection-local PRAGMAs through the modernc DSN or a connection hook; test contention across two handles. [Busy handlers belong to individual connections](https://sqlite.org/c3ref/busy_timeout.html).

6. **HIGH — [design.md:177, migration](specs/memory/tiramemsu/design.md:177): older writers can silently fork the graph.** Current `migrate` accepts a schema version greater than its migration list. An old binary can therefore open an upgraded database, write `triples`, and report success while the new engine ignores those writes. **Fix:** make the retained legacy table reject writes with an upgrade error, and add newer-version rejection for future releases. Test upgrade → old writer → reopen.

7. **MEDIUM — [design.md:74, FTS schema](specs/memory/tiramemsu/design.md:74): external content and indexed content differ.** The content table contains numeric terms, but the trigger indexes only entity/string terms. A probe failed external-content integrity checking; rebuilding then made previously excluded numeric text searchable. **Fix:** point FTS at a filtered content view, or use a standalone FTS table containing exactly the searchable terms. Test integrity checking and rebuild equivalence. [FTS5 external-content requirements](https://sqlite.org/fts5.html#external_content_table_pitfalls).

8. **MEDIUM — [design.md:144, Views](specs/memory/tiramemsu/design.md:144): composite reads have no snapshot contract.** Applying predicates independently does not make `Explain` or `Conflicts` consistent: a writer can commit between reading a fact and reading its evidence. Tiramemsu executes each read in one snapshot. **Fix:** bind each operation to a read transaction, or freeze a committed transaction number for all its scans. With `:memory:` limited to one connection, all nested reads must use that same executor.

9. **MEDIUM — [design.md:146, generic view filtering](specs/memory/tiramemsu/design.md:146): statement predicates cannot implement event-log filtering.** Applying `Now`’s `t_ret IS NULL` removes the events of retracted statements, defeating replay. Tiramemsu’s actual `read::events_since` reads the whole snapshot log and orders by `(t,op,eid)`; it does not apply statement visibility. **Fix:** specify event semantics separately, including any transaction cutoff and assert-before-retract ordering. Test assertion and retraction within the same transaction.

10. **MEDIUM — [requirements.md:72, view-aware Conflicts](specs/memory/tiramemsu/requirements.md:72): History produces false disagreements.** A corrected old value and its replacement can overlap in valid time while never being believed simultaneously. The proposed History predicate includes both. Tiramemsu explicitly rejects conflict inspection on History in `conflict.rs:192`. **Fix:** reject that combination, or require overlap in transaction time too. Add a correction-without-simultaneous-conflict test.

11. **MEDIUM — [design.md:139, schema caching](specs/memory/tiramemsu/design.md:139): caching for the transaction’s lifetime makes schema changes ineffective within that transaction.** An assertion can cache “many”; `SetPredicate(...One:true)` then changes the graph, but the next assertion still uses “many”. Tiramemsu invalidates its cache on relevant writes and retractions. **Fix:** remove the cache initially, or invalidate it on every schema mutation. Test read → schema change → constrained write in one callback.

12. **MEDIUM — [design.md:110, verbs](specs/memory/tiramemsu/design.md:110): interval validation is missing.** Neither the schema nor the verb algorithms reject `v_from >= v_to`. The overlap expression alone does not validate an interval; even an empty interval can match an existing unbounded fact. Tiramemsu calls `Valid::check` before lookup and validates patched intervals. **Fix:** require this for Assert/Create/Derive/Supersede and test empty/reversed intervals, including rollback.

13. **MEDIUM — [design.md:136, Derive](specs/memory/tiramemsu/design.md:136): empty support sets are accepted by the stated rules.** “Every support is live” holds vacuously for an empty list. Exact-set lookup could then return an independently asserted fact, since its support set is also empty. Tiramemsu rejects empty support explicitly. **Fix:** require at least one support before lookup and test that an empty-support derivation fails without changing the graph.

14. **MEDIUM — [design.md:135, Confirm](specs/memory/tiramemsu/design.md:135): `Create` inflates confirmation counts.** Calling Confirm twice within one transaction creates two identical confirmation statements for the same corroborating transaction. Tiramemsu uses its idempotent write path. **Fix:** use engine-authorized Assert; test that repeated confirmation within one transaction produces one link, while confirmation in another transaction produces another.

15. **MEDIUM — [design.md:167, legacy Invalidate](specs/memory/tiramemsu/design.md:167): invalidation extends already-ended facts.** Closed intervals remain transaction-live. Superseding *every live match* therefore moves an old episode’s end forward, and repeated invalidation keeps extending it. Current `InvalidateTriple` updates only `valid_to IS NULL`. **Fix:** preserve that selection rule in the compatibility facade. Test repeated invalidation and coexistence of closed and open episodes.

16. **MEDIUM — [design.md:180, legacy extraction time](specs/memory/tiramemsu/design.md:180): synthetic transaction instants do not preserve extraction timestamps.** Existing `InsertTriple` stores RFC3339 timestamps at second precision, so ties are ordinary. Import changes subsequent tied instants by milliseconds, with no separate original timestamp retained in the new graph. **Fix:** preserve original extraction time independently and populate `Triple.ExtractedAt` from it. Test tied timestamps and exact round trips, not just ordering.

17. **MEDIUM — [design.md:183, legacy import through Create](specs/memory/tiramemsu/design.md:183): previously legal `sys:` predicates cannot migrate correctly.** Current Add accepts them. New Create rejects them, and About excludes them even if import bypasses validation. Thus some valid existing databases either fail upgrade or lose visible facts. **Fix:** define a collision-safe legacy vocabulary mapping and preserve original predicate names through the compatibility facade. Include a v5 fixture containing reserved-name collisions.

18. **MEDIUM — [design.md:171, store API removal](specs/memory/tiramemsu/design.md:171): “nothing outside kg.go called them” is false.** [sqlite_store_test.go:414](internal/palace/sqlite_store_test.go:414) and `sqlite_store_edge_test.go:248` call the removed methods directly. Step 10 consequently breaks compilation, beyond the listed behavioral test updates. **Fix:** explicitly migrate those tests and preserve their coverage, or retain adapters backed by the new engine.

19. **MEDIUM — [requirements.md:94, KGStats](specs/memory/tiramemsu/requirements.md:94): new counts lack a compatibility mapping.** Transaction-live facts include ended intervals, whereas existing `ActiveTriples` counts `valid_to IS NULL`. Supersede also adds historical versions that would inflate a naïve `TripleCount`. Existing tests assert these distinctions, and palace-status renders those fields directly. **Fix:** retain defined legacy projections and add separate statement/layer/retraction/transaction counts; test status after invalidation and correction.

20. **MEDIUM — [design.md:193, tool extensions](specs/memory/tiramemsu/design.md:193): alternative inputs require schema changes, not just handler branches.** Current `subject` and `entity` fields are required. Annotation calls using only `about`, and searches using only `text`, would fail before reaching their handlers. **Fix:** make those fields optional in the inferred schema, validate the alternative combinations, and invoke both cases through `tool.Run`. [ADK documents this required-field behavior](https://github.com/google/adk-docs/blob/main/docs/tools-custom/function-tools.md).

21. **LOW — [design.md:173, optional DB discovery](specs/memory/tiramemsu/design.md:173): runtime capability probing adds an avoidable failure mode.** A valid `PalaceStore` wrapper can satisfy today’s constructor contract yet suddenly make every KG call return `ErrKGUnavailable` because it lacks `DB()`. The change supports only SQLite anyway. **Fix:** inject the engine or database explicitly at construction, or express the required capability in a compile-time interface.
